# Export des Verfügbarkeitsberichts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Die Berichtsseite liefert mit einem Klick eine ZIP-Datei mit PDF, Excel und allen Bildern (PNG) und kann PDF, Excel und die Bilder einer einzelnen Gruppe auch einzeln laden.

**Architecture:** Die Grafiken entstehen als SVG-Zeichenketten in reinen Funktionen (`src/lib/report/export/`), `sharp` macht daraus PNG. Excel baut `exceljs`, PDF baut `pdf-lib`, die ZIP-Datei schreibt `fflate` als Datenstrom. Eine Funktion `exportFiles` erzeugt alle Dateien nacheinander (Gruppe für Gruppe) und dient der Route und später dem Mailversand (Issue #65 im Fork).

**Tech Stack:** Next.js Route Handler, `sharp` 0.35.3 (vorhanden), `exceljs` 4.4.0, `pdf-lib` 1.17.1, `fflate` 0.8.3, `node:test` mit `tsx`, Playwright (JSON-Route).

**Spec:** `docs/superpowers/specs/2026-11-12-berichtsexport-design.md` (Abschnitte 3, 5, 6). Voraussetzung ist PR #67 im Fork (GitHub, Gruppenblatt, Typen `GroupSheetData`, `GroupListEntry`, `heat.ts`). Dieser Plan setzt auf `main` nach dem Merge von PR #67 auf.

## Global Constraints

- Branch `feature/50-export` von `main`, nie direkt auf `main`. Commit `<typ>(<scope>): <Imperativ> (#50)`, erste Zeile höchstens 50 Zeichen, Anhang `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

- Bilder: PNG, weißer Hintergrund, **2000 px Breite**. Farben Blau über Gelb zu Rot (kein Grün): Schwerer Ausfall `#c8402f`, Teilausfall `#e8903a`, Eingeschränkt `#999999`, Farbstufen der Wärmekarte aus `src/lib/report/export/palette.ts`.
- Wärmekarte höchstens 12 Zeilen je Bild (`chunkRows` aus `@/lib/report/heat`).
- Dateinamen ohne Umlaute und Leerzeichen (ASCII, Kleinbuchstaben, `-`). Gleiche Namen bekommen `-<id>` angehängt.
- Das Rendern läuft Gruppe für Gruppe nacheinander, nie alle Bilder gleichzeitig im Speicher (außer den fertigen PNG im PDF).
- Beschriftungen über `ta('English', 'Deutsch')`. Zugriff nur für angemeldete Nutzer (Status 401), im Testmodus offen wie `/api/availability-report` (`isTestMode()`).
- Neue Abhängigkeit nur die vier oben genannten, mit genau diesen Versionen.
- Prüfen mit `npm run test:unit`, `npx tsc --noEmit`, `npm run lint`. E2E nach `docs/src/development/testing.md`, Umgebung von Hand starten, wenn `scripts/run-e2e-tests.sh` nach 2,5 Minuten abbricht (kalter `npm install`).

## Review Focus

- Dienst- und Gruppennamen mit `&`, `<`, `"`, Umlauten und sehr langer Länge: das SVG bleibt gültig (sonst wirft `sharp`), lange Namen laufen nicht aus dem Bild (Task 3, 4).
- Gruppenname mit `/`, mit Umlauten oder zwei Gruppen mit gleichem Namen: Pfad in der ZIP-Datei bleibt eindeutig und ASCII (Task 6).
- Bericht ohne Dienste, ohne Störungen oder mit Verfügbarkeit `null`: Bilder, Excel und PDF entstehen trotzdem, Excel schreibt leere Zellen statt 0 (Task 3 bis 6).
- Gruppe mit einem Dienst und Gruppe ohne Störungen im Monat: Blatt entsteht ohne Block 3 und 4 (Task 4).
- Anonyme Anfrage bekommt 401, ungültiger Zeitraum, ungültige Gruppe oder unbekanntes `format` bekommen 400 (Task 7).
- Speicher: Der Export mit 36 Gruppen und 166 Diensten läuft nacheinander und bleibt bei zwei gleichzeitigen Aufrufen unter 768 MiB (Messung Task 8, nicht automatisch testbar).
